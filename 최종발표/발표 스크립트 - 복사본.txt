지능형 웹서비스개발 2회차 D팀 시연 시작하겠습니다.

저희팀 주제는 날씨와 위치정보를 활용한 음식추천 지능형 웹사이트 이고,
사용기술은 ~~ 

기존 추천 서비스 분석해본 결과 단순 카테고리에 의한 서비스이거나 
사용자의 상황(계절, 시간, 날씨)를 반영하지 않는 서비스가 많았다

어떤 서비스는 음식을 사용자의 의도로만 선택하게 구성하여 매일 하게되는 음식 선택 경험이 피로로 다가오는 경우

기존 서비스의 아쉬운 점들을 보완하고자 위치 정보와 실시간 날씨를 활용한 지능형 음식 추천 서비스를 기획하였고,

추천 음식과 해당하는 카테고리의 음식점에 랭킹을 매겨 가장 점수가 높은 항목을 제공할 수 있도록


이를 통해 사용자의 상황에 적합한 항목들을 추천할 수 있어 서비스 품질의 향상을 기대할 수 있겠고, 

매일 반복되는 음식 선택 과정이 불쾌한 경험이 되지 않도록 했

또한 사용자의 검색기록, 추천받은 기록, 선택한 음식과 음식점을 수집하여 추후 서비스의 품질을 고도화 했


접속

사용자가 접속하게 되면 기본 UI가 표시되는 화면 응답
이후 클라이언트는 Kakao 에 지도를 요청

html 전달은 처음 한 번의 요청에서 끝나고
사실상 대부분의 기능을 
자바스크립트의 fetch()를 사용하여 비동기 처리

서비스에서 많은 영역을 차지하는 지도 객체가 생성 되어야만 후속 기능 실행
렌더링에 실패 할 경우 서비스 오류가 발생했다는 응답을 돌려

사용자에게 즉시 보이는 화면을 먼저 확보하여 초기 UX 안정성을 향상


위치, 날씨

이후 사용자에게 위치 정보 활용에 동의?
O > 활용해 날씨, 음식 , 음식점을 추천
X > 기본좌표로 서비스하게 됨

날씨와 추천음식 요청 시 처리 속도를 줄이기 위해 백그라운드에서 각각의 기능을 병렬로 처리

추천이 나오게 되면
서비스 품질을 높이기 위해 각각의 정보를 캐싱하여 반응성을 향상



음식 추천

사전에 수집한 날씨 데이터를 K-mean 학습한 엔진에서 현재 날씨와 패턴이 가장 유사한 군집을 3위까지 선정하여 추천

정답 라벨이 없는 날씨 데이터 특성상,
유사한 상황을 묶는 군집 기반 접근이 더 적합하다고 판단 k-means
사용자의 현재 날씨와 시간을 하나의 상황으로 해석하고,
가장 유사한 패턴의 군집을 찾아 음식 카테고리를 추천하는 구조



음식점 추천

카테고리에 해당하는 음식점 목록을 소상공인 상권 데이터에서 추출하였으며
이때 사용자와의 거리 수집한 리뷰의 감성점수, 리뷰 개수 점수로 각각 가중치를 매겨 랭킹 형식으로 추천 합

네이버 플레이스에서 셀레니움으로 크롤링한 리뷰데이터를 준지도학습 방식으로 소량 라벨링 후 LR이 반복 재학습
음식점 추천 품질을 높이는데 활용


예측 품질을 높이기 위해 konlpy로 명사,형용사,동사만 추출해 토큰화 하였으며
단어의 빈도와 희귀도를 고려하는 TF-IDF벡터화 사용
특성의 중요도를 해석하는데 용이하고 튜닝이 쉬운 로지스틱 회귀로 벡터를 분류


최신 딥러닝 모델을 적용하지 못한 아쉬움은 있으나,
데이터 특성과 서비스 목적에 적합한
설명 가능한 모델을 선택하여 안정적인 추천 구조를 구현했습니다.



이용자 검색로그와 사회적인 이벤트(지역행사, 스포츠 시즌 등)의 
상관관계를 분석하여 향후 뉴스, sns등의 정보와 연결하여
시즌별 음식 추천기능을 개선할 수 있도록 
기초데이터 생성(이용자 검색로그)까지 마쳤다

이상 시연 마치겠습니다.
